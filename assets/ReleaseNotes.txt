Version 0.3.0 - May 29, 2026

🔒 SECURITY IMPROVEMENTS — proactive hardening
▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔
- Stronger key derivation: the master password now uses argon2id (64 MB, 3 passes,
  4 lanes) instead of PBKDF2, with a random per-install salt stored inside the
  database. This replaces the previous shared, hard-coded salt.
- Full-field encryption at rest: every sensitive connection field is now encrypted
  (name, host, username, SSH key path, key passphrase, remote and rsync paths, SSH
  extra arguments, password, and the LAN file-agent TLS pin). Previously only the
  password, key passphrase, and TLS pin were encrypted; host names, usernames and
  jump-host arguments were stored in clear text.
- Optional OS keychain: the master password can be cached in this computer's
  operating-system keychain (macOS Keychain, Windows Credential Manager, Linux
  Secret Service) so you are not prompted at every launch. Off by default; enable
  it in Application Settings. The keychain only ever holds the master password.
- Portable by design: the salt and encryption parameters travel inside the
  database file. Copy the app and connections.db to another computer (which has no
  keychain entry) and it simply prompts for the master password again.
- Optional master password hint: set a hint that is shown after two failed login
  attempts. Set or clear it from Change Master Password. The hint is stored
  unencrypted, so do not put the password itself in it.
- Automatic, transparent upgrade: databases created by earlier versions are
  re-encrypted to the new scheme the first time you unlock them with the correct
  password. No manual steps, and the AES-256-GCM cipher itself is unchanged.
- No recovery by design: there is still no back door. A fresh computer with only
  the database and no keychain entry will require the master password.

Version 0.2.0 - April 22, 2026
- LAN file agent (TLS 1.3 + PSK): headless mode (-file-agent / -file-agent-*), GUI window from Tools,
  receiver command helper, virtual paths under -file-agent-root, FILEMOVER_FILEAGENT_DEBUG diagnostics.
- Intended for peers on the same local network segment (private/link-local). For routed subnets,
  VLANs, or port-forward setups, use SFTP, SCP, or SMB instead — the agent is not aimed at that.
- Tray: Show/Hide walks all tracked windows; dialog stacking fixes for Help, password, file agent.
- Windows: console attach for headless/help with -H windowsgui; compile scripts: module cache,
  GOWORK=off, -mod=mod, synced-tree / SSH path notes.
- macOS/Linux compile scripts: cd to repo root, committed go.mod (no fyne@latest in compile-mac),
  native dev binary copied to ./filemover for buildrun.sh; build-config KB_VERSION_DEFAULT is the
  packaging default (bump with ./setver.sh).
- Version tooling: ./setver.sh fixes main.go appVersion, Info.plist sample, winres, Inno, FyneApp.toml,
  KB_VERSION_DEFAULT (package.sh reads the latter).
- Repo hygiene: removed unused assets/sounds and extra mascot images; packaging no longer expects sounds.
  Info-plist icon file name aligned with KrankyBearCowboyBrown.icns.
